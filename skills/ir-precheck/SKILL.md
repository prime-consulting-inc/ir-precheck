# ir-precheck（IR開示の提出前チェック）

自社が提出・掲載する前の開示資料を、同梱の `scripts/ir_precheck.py` で点検し、結果を「要修正／要確認／情報」に分けて伝えます。このチェックは機械で拾える形式面の確認です。開示してよいかの判断ではありません。

## 対象と対象外

- 対象は、利用者の会社が提出・掲載する前のファイルです。TDnetに出すPDFは必ず点検し、元のWord・PowerPointがあればあわせて点検します。
- 他社が公開済みの資料は対象外です。黒塗りや伏せ字の下の文字を取り出す、まとめる、推測する依頼には応じません。`--redact-words` も自社のファイル以外には使いません。
- 原本は変更しません。

## 実行前に決めること

1. 次の4項目を確かめます。依頼文やファイル名に書かれていればそれを使い、なければ表紙（1ページ目）から読み取って、利用者に一度だけ確認します。返事がなければ読み取った値で実行し、その旨を報告の冒頭に書きます。
   - 会社名（`--company`）
   - 証券コード（`--code`）
   - 対象決算期（`--period`。例：2027年3月期）
   - 開示予定日（`--date`）
2. 支援会社名・社内の案件名がわかれば `--ng-words` に、黒塗りした語がわかれば `--redact-words` に渡します。わからなければ省略します。
3. 複数のPDFを開示する場合は、開示する順に並べて1回で渡します。

## 実行

スクリプトは、このSKILL.mdと同じフォルダの `scripts/ir_precheck.py` です。以下の `<スキルのフォルダ>` は、このSKILL.mdがあるフォルダの絶対パスに置き換えて実行します（Claude Code では `${CLAUDE_SKILL_DIR}` で参照できます）。

```bash
python3 <スキルのフォルダ>/scripts/ir_precheck.py --json \
  --company "〇〇株式会社" --code 1234 --period "2027年3月期" --date 2026-11-13 \
  提出予定.pdf 説明会資料.pptx
```

`python3` がなければ `python` または `py -3` で実行します。PyMuPDF などのライブラリがないときは「未検査」と出るので、`pip install -r <スキルのフォルダ>/requirements.txt` を実行してから再実行します。

結果は `--json` の出力で判断します。

| 状態 | 見分け方 | 伝え方 |
|---|---|---|
| 検査できなかった | `worst` が「未検査」、終了コード3 | `unchecked` のファイルは未検査と伝え、理由（パスワード付き、未対応の形式など）を書きます。指摘なしとは書きません |
| 要修正あり | `worst` が「要修正」、終了コード2 | 修正してから再実行するよう伝えます |
| 要確認のみ | `worst` が「要確認」、終了コード1 | 各項目を本文で確かめるよう伝えます |
| 指摘なし・情報のみ | `worst` が null または「情報」、終了コード0 | 「機械チェックでの指摘はありません」と伝え、目視チェックへ進みます |

複数のファイルを渡したときは、ファイルごとの `worst` も見ます。1つが未検査でも、ほかのファイルの指摘は伝えます。

## 報告の書き方

ファイルごとに、未検査、要修正、要確認の順で書きます。各項目には次の3点を入れます。

- 場所：ページ番号・スライド番号・セル番地。文書のプロパティは「文書のプロパティ ＞ タイトル」のように画面上の名前で書きます。
- 内容：何が残っているか。
- 直し方：どのソフトのどの操作で直すか（下の表）。

「情報」は件数と種類を1〜2行でまとめ、全件は並べません。

黒塗り・伏せ字・白文字・隠し文字の下にある文字列は、報告にも会話にも書きません。スクリプトも場所と件数だけを出します。利用者がファイルを開いて読める場合でも、こちらから読み上げません。

### 区分ごとの直し方

| 区分 | 直し方 |
|---|---|
| メタデータ（タイトル・作成者等） | Word・PowerPointは「ファイル ＞ 情報 ＞ プロパティ」で直してからPDFにし直します。PDFだけを直す場合はAcrobatの「ファイル ＞ プロパティ」で直すか、`--clean-metadata` で公開用コピーを作ります |
| 注釈・コメント | 元のファイルでコメントを削除してPDFにし直します。Acrobatなら注釈の一覧から削除します |
| 墨消し未適用 | Acrobatで「墨消しを適用」を実行して保存し直します |
| 黒塗りの残存・伏せテキストの残存・覆われた画像 | 図形を重ねても下の文字や画像は消えません。元のファイルで該当の文字・画像を削除するか、Acrobatの「墨消し」で処理します。処理後に全選択してメモ帳に貼り、伏せた語が出てこないことを確かめます |
| 発表者ノート・非表示スライド | PDFに書き出すとき、ノートと非表示スライドを含めない設定にします。PowerPointのファイル自体を公開する場合は削除します |
| 社外秘マーク・レビュー文言 | 元のファイルから削除します。スライドマスター・ヘッダー・透かしも確かめます |
| 隠し文字・変更履歴（Word） | 隠し文字は削除し、変更履歴は「校閲 ＞ すべての変更を承諾」のあと保存し直します |
| セキュリティ（パスワード・権限） | パスワードと印刷・コピー禁止の設定を外して保存し直します |
| 日付と曜日 | 日付と曜日のどちらが正しいかを確かめて直します |

## 誤検知の扱い

- 次の区分は、文脈にかかわらず「要修正」のまま伝えます：黒塗りの残存、伏せテキストの残存、覆われた画像、墨消し未適用、注釈、コメント、隠し文字、パスワード・権限、埋め込みファイル、非表示レイヤー。
- 「要確認」の項目は、本文を読んで通常の開示の表現だと判断できる場合、その理由を1行添えて「確認したうえで問題なし」と書いてかまいません。例：商品名の「ドラフト」、取引先として書かれた他社名、前期の数値を示すための前の決算期。
- 判断がつかないものは「要確認」のまま残します。

## 公開用コピー

文書のプロパティだけを消したPDFが必要なら、別の名前で書き出します。

```bash
python3 <スキルのフォルダ>/scripts/ir_precheck.py --clean-metadata 公開用.pdf 提出予定.pdf
```

書き出した `公開用.pdf` にも、通常のチェックをもう一度実行します。このコピーで消えるのは文書のプロパティだけで、注釈・黒塗り・本文は直りません。

## 目視チェックへの引き継ぎ

最後に 同じフォルダの `references/manual_checklist.md` を渡し、作成者とは別の人が確認するよう伝えます。グラフと数値の一致、他社ロゴ、中期経営計画との整合、画像化された文字、TDnetのプロパティ確認画面は、このチェックでは見ていません。

報告の末尾には次の一文を必ず入れます。

> このチェックは機械で拾える項目だけを見ています。指摘がないことは、開示してよいことの確認にはなりません。
